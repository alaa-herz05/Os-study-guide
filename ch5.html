1. Basic Concepts

Why we schedule the CPU at all.

Multiprogramming and the ready queue

On a system with a single CPU core, only one process can run at a time. Other processes must wait until the core is free and can be rescheduled. The objective of multiprogramming is to have some process running at all times, to maximize CPU utilization.

CPU–I/O burst cycle

Process execution is an alternating sequence of CPU bursts and I/O bursts. A process runs on the CPU, then waits for I/O, then runs again, and so on.

CPU scheduler

Whenever the CPU becomes idle, the OS must select one process from the ready queue. The CPU scheduler selects a process from those in memory that are ready to execute and allocates the CPU to it.
  • The ready queue is not necessarily FIFO. It can be a FIFO queue, a priority queue, a tree, or an unordered linked list.
  • Conceptually, all processes in the ready queue are lined up waiting for a chance to run. The records in the queues are generally the PCBs of the processes.

2. The Dispatcher

The module that actually hands the CPU to the chosen process.

What the dispatcher does

The dispatcher gives control of the CPU’s core to the process selected by the CPU scheduler. This involves:
  • Switching context from one process to another
  • Switching to user mode
  • Jumping to the proper location in the user program to resume it
The dispatcher should be as fast as possible, since it is invoked during every context switch.

Dispatch latency

The time it takes the dispatcher to stop one process and start another running.

Scheduler vs dispatcher

Scheduler = chooses which ready process runs next.
Dispatcher = gives the CPU to that process (context switch, user mode, jump).

3. Scheduling Criteria

How we judge whether an algorithm is good. The choice of criteria can change which algorithm looks best.

CPU utilization

Keep the CPU as busy as possible. Conceptually 0 to 100%; in a real system it should range from 40% to 90%.

Throughput

The number of processes completed per time unit.

Turnaround time

From submission to completion. It is the sum of the periods spent waiting in the ready queue, executing on the CPU, and doing I/O.

Waiting time

The sum of the periods spent waiting in the ready queue.

Response time

From submission of a request until the first response is produced: the time to start responding, not the time to output the whole response.
Typical goal: maximize CPU utilization and throughput; minimize turnaround, waiting and response time.

4. Scheduling Algorithms

Decide which process in the ready queue gets the CPU. Explained for a single CPU with one core. Tap to open each.

1. First-Come, First-Served (FCFS)
The process that requests the CPU first is allocated the CPU first. Implemented with a FIFO queue: when a process enters the ready queue its PCB is linked onto the tail; when the CPU is free it goes to the process at the head, which is then removed from the queue. The code is simple to write and understand.
A Gantt chart is a bar chart that illustrates a particular schedule, including the start and finish times of each process.
Example (all arrive at 0): P1 = 24 ms, P2 = 3 ms, P3 = 3 ms in the order P1, P2, P3 → waiting times 0, 24, 27 → average waiting time = 17 ms. A short job stuck behind a long one waits a long time.
2. Shortest-Job-First (SJF)
Associates with each process the length of its next CPU burst. When the CPU is available it goes to the process with the smallest next CPU burst. If two next bursts are equal, FCFS breaks the tie.
Example: P1 = 6, P2 = 8, P3 = 7, P4 = 3 → order P4, P1, P3, P2 → waiting times 0, 3, 9, 16 → average = 7 ms.
3. Round-Robin (RR)
Similar to FCFS but with preemption added so the system can switch between processes. A small unit of time, the time quantum (time slice), is defined, generally 10 to 100 ms. The ready queue is a circular queue; the scheduler goes around it, giving each process the CPU for up to 1 time quantum.
  • No process gets the CPU for more than 1 quantum in a row (unless it is the only runnable process).
  • If a burst exceeds 1 quantum, the process is preempted and put back in the ready queue. So RR is preemptive.
  • Performance depends heavily on the size of the quantum: if it is extremely large, RR is the same as FCFS; if it is extremely small (say 1 ms), RR causes a large number of context switches.
Example (quantum = 4 ms): P1 = 24, P2 = 3, P3 = 3 → average waiting time ≈ 5.66 ms.
4. Priority scheduling
A priority is associated with each process, and the CPU goes to the process with the highest priority. Equal priorities are scheduled FCFS. SJF is simply a priority algorithm where the priority is the inverse of the (predicted) next CPU burst: the larger the burst, the lower the priority.
  • Major problem: indefinite blocking, or starvation. A ready process waiting for the CPU is effectively blocked; low-priority processes may wait indefinitely.
  • Solution: aging – gradually increasing the priority of processes that wait in the system for a long time.
Example (smaller number = higher priority): bursts P1..P5 = 10, 1, 2, 1, 5 with priorities 3, 1, 4, 5, 2 → order P2, P5, P1, P3, P4 → average waiting time = 8.2 ms.

6. Chapter Summary

Review this right before the exam.

  • Single core = one process at a time; multiprogramming keeps the CPU busy. Processes alternate CPU and I/O bursts.
  • The CPU scheduler picks from the ready queue (FIFO, priority queue, tree, list of PCBs); the dispatcher performs the switch (context, user mode, jump). Dispatch latency = time to switch.
  • Criteria: CPU utilization (40–90%), throughput, turnaround, waiting, response.
  • FCFS: FIFO, simple, long waits behind long jobs. SJF: smallest next burst. RR: time quantum (10–100 ms), preemptive, circular queue. Priority: highest priority first, FCFS ties.
  • Priority problem: starvation; fix: aging. SJF is priority = inverse of predicted burst.
  • RR quantum: huge → FCFS; tiny → too many context switches.
