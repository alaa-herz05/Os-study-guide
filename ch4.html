1. What is a Thread?

The basic unit of CPU utilization inside a process.

Definitions

All modern operating systems let a process contain multiple threads of control. Several ways to say it:
  • A thread is a path of execution within a process.
  • A thread is a basic unit of CPU utilization.
  • A thread is a flow of control within a process.
  • A thread of execution is the smallest sequence of programmed instructions that can be managed independently by a scheduler (typically part of the OS).

What a thread has, and what it shares

A thread comprises a thread ID, a program counter, a register set, and a stack. It shares with the other threads of the same process its code section, data section, and other OS resources such as open files and signals.

Components of a thread

  • A thread ID that uniquely identifies it
  • A register set representing the processor status
  • A user stack (when running in user mode) and a kernel stack (when running in kernel mode)
  • A private storage area used by run-time libraries and dynamic link libraries (DLLs)

Multithreading

Allows multiple parts of a program to execute at the same time. These parts are the threads: lightweight processes inside the process. Multithreading leads to maximum utilization of the CPU by multitasking.

2. Advantages of Threads over Processes

Six reasons threads are used.

Responsiveness

If a process is divided into threads and one thread completes, its output can be returned immediately.

Faster context switch

Context-switch time between threads is lower than between processes, which need more CPU overhead.

Use of multiprocessors

Multiple threads of one process can be scheduled on multiple processors, making execution faster.

Resource sharing

Code, data and files are shared among all threads of a process.
Stack and registers can’t be shared. Each thread has its own.

Easier communication

Threads share a common address space. Processes must use specific communication techniques.

Enhanced throughput

If each thread function is a job, more jobs complete per unit of time.

3. User Threads and Kernel Threads

Two types of threads in a modern system.

User threads

Supported above the kernel, without kernel support. These are the threads that application programmers put into their programs.

Kernel threads

Supported within the kernel of the OS itself. All modern OSes support them, allowing the kernel to perform multiple simultaneous tasks and/or service multiple kernel system calls simultaneously.
In a specific implementation, user threads must be mapped to kernel threads using one of three strategies: the multithreading models in the next section.

4. Multithreading Models

How user threads relate to kernel threads.

Many-to-One

Maps many user threads to a single kernel thread.
  • + Quite efficient: thread management is done in user space
  • − A blocking system call blocks the entire process
  • − No parallel run: only one thread can access the kernel at a time
  • − One kernel thread runs on one CPU, so a process can’t be split across CPUs

One-to-One

Maps each user thread to a kernel thread.
  • + Many threads run in parallel on multiprocessors
  • + Other threads run when one makes a blocking system call
  • − Creating a user thread requires creating a kernel thread
  • − Many kernel threads burden the system, so the number of threads is restricted

Many-to-Many

Multiplexes many user threads onto an equal or smaller number of kernel threads.
  • + No restriction on the number of user threads
  • + Blocking kernel calls don’t block the entire process
  • + Processes can be split across multiple processors
  • + A process can get a variable number of kernel threads depending on CPUs and other factors
It has none of the disadvantages of the other two.

Two-tier model

A popular variation of many-to-many that allows either many-to-many or one-to-one operation. Used by IRIX, HP-UX, Tru64 UNIX, and Solaris before Solaris 9.

5. Chapter Summary

Review this right before the exam.

  • A thread = basic unit of CPU utilization: thread ID, program counter, register set, stack.
  • Threads of one process share code, data, open files, signals; each has its own stack and registers.
  • A traditional heavyweight process has one thread; multithreading gives lightweight parallel tasks and max CPU use.
  • Advantages: responsiveness, faster context switch, multiprocessor use, resource sharing, easier communication, higher throughput.
  • User threads (above the kernel, no kernel support) vs kernel threads (supported by the OS kernel).
  • Models: many-to-one, one-to-one, many-to-many (plus two-tier).
