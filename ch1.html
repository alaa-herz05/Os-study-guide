1. What Operating Systems Do

The big picture: what an OS is and why every computer needs one.

Definition

An operating system (OS) is software that manages a computer’s hardware. It provides a basis for application programs and acts as an intermediary between the computer user and the hardware.
Users
Application programs (browser, games, Word)
Operating System (kernel)
Hardware (CPU, memory, I/O devices)

The kernel

The one program that is running at all times on the computer is the kernel. It is the core part of the operating system.

OS goals

  • Execute user programs and make solving user problems easier
  • Make the computer system convenient to use
  • Use the hardware in an efficient manner

2. Computer-System Organization

How the CPU, memory and devices are connected and work together.

How the parts connect

One or more CPUs and device controllers are connected through a common bus that gives access to shared memory. The CPUs and devices run concurrently and compete for memory cycles.
CPU 1CPU 2MemoryDisk controllerUSB controllerGraphics adapter
Common system bus

Device controller = hardware

Each controller is in charge of one particular device type and has a local buffer (temporary storage). Example: USB = Universal Serial Bus.

Device driver = software

Each controller type has an OS device driver to manage it. It provides a uniform interface between the controller and the kernel.

How an I/O operation works

  • I/O devices and the CPU can execute concurrently.
  • The CPU moves data between main memory and the controller’s local buffers.
  • I/O itself goes from the device to the local buffer of the controller.
  • When finished, the controller informs the CPU by causing an interrupt.

3. Interrupts

The mechanism that makes an OS “interrupt driven”.

What is an interrupt?

A signal emitted by hardware or software when a process or event needs immediate attention. It alerts the processor to a high-priority event that requires interrupting the current work.
  • The interrupt is handled by the Interrupt Service Routine (ISR).
  • The processor first completes the current instruction i, then loads the Program Counter (PC) with the address of the ISR’s first instruction.
  • The address of the interrupted instruction is saved in a temporary location, so the CPU can continue with i+1 afterwards.

Common functions

  • Control transfers to the ISR through the interrupt vector, which holds the addresses of all service routines
  • The architecture must save the address of the interrupted instruction
  • An operating system is interrupt driven

Trap / exception

A software-generated interrupt caused either by an error (e.g. divide by zero) or by a user request (system call).

Interactive: interrupt handling step by step

  1. CPU is running a user program (instruction i).
  2. A device controller finishes its job and raises an interrupt.
  3. CPU finishes instruction i; OS saves the state (registers + program counter).
  4. OS determines the interrupt type and uses the interrupt vector to jump to the right ISR.
  5. The ISR (separate code for each interrupt type) runs and handles the event.
  6. State is restored and the CPU resumes the program at i+1.

4. Computer Startup & Storage Hierarchy

How a computer wakes up, and why memory comes in layers.

Bootstrap program

  • Loaded at power-up or reboot
  • Stored in ROM or EPROM, generally known as firmware
  • Initializes all aspects of the system
  • Loads the OS kernel and starts its execution

Storage hierarchy

Storage is organized in a hierarchy by speed, cost and volatility.
Registers
Cache
Main memory (RAM) – volatile
Solid-state / electronic disk
Hard disk, optical disk, magnetic tape – non-volatile

Caching = copying information into a faster storage system. Main memory can be viewed as a cache for secondary storage. Volatile storage loses its contents when power is off.

5. Direct Memory Access (DMA)

Letting fast devices talk to memory without bothering the CPU.

DMA allows an I/O device to send or receive data directly to or from main memory, bypassing the CPU. It is managed by a chip called the DMA controller (DMAC).
  • Used for high-speed I/O devices that transfer at close to memory speed.
  • The device controller moves whole blocks of data from its buffer straight to main memory without CPU intervention.
  • Only one interrupt per block is generated, instead of one interrupt per byte.
Result: the CPU is free to do other work while data is being transferred.

6. Types of Operating Systems

Tap each type to open it.

1. Batch OS
The user does not interact with the computer directly. An operator groups jobs with similar requirements into batches and submits them.
Examples: payroll systems, bank statement systems.
2. Multiprogrammed OS
More than one job is in main memory at the same time. When the running job waits for I/O (the CPU would be idle), the OS switches to another job in memory. This keeps the CPU busy.
3. Time-Sharing OS (Multitasking)
Each task gets a small slice of CPU time called a quantum. When it expires, the OS switches to the next task, so every user feels like they own the whole system. Tasks can come from one user or many.
4. Distributed OS
Connects multiple computers through a common communication network. Each system has its own CPU and memory, and remote access is available.
5. Network OS
Connects autonomous computers over a network to support workstations and share databases, applications, files and printers.
Examples: Windows Server 2003/2008, UNIX, Linux, Mac OS X.
6. Real-Time OS (RTOS)
Serves real-time systems where the response time (time to process and respond to input) must be very small.
  • Hard real-time: strict deadlines; even the shortest delay is unacceptable (automatic parachutes, airbags). Virtual memory is rarely found.
  • Soft real-time: time constraints are less strict.
7. Multiprocessor OS
Used on systems with multiple processors to increase speed and computing power.
  • Advantages: parallel execution, higher throughput, reliability (if one processor fails the system keeps working).
  • Disadvantages: high cost and more complex (scheduling issues).

7. Dual-Mode Operation & Timer

How the OS protects itself and keeps control of the CPU.

Dual-mode operation

Lets the OS protect itself and other system components using two modes, selected by a mode bit provided by hardware: user mode (running a user program) and kernel mode (kernel code executing).
USER MODE · bit 1
A user program is running. It cannot run privileged instructions directly.

Timer

Prevents an infinite loop or a process hogging resources.
  • The timer is set to interrupt the computer after some period.
  • A counter is decremented by the physical clock; the OS sets it (a privileged instruction).
  • When the counter reaches zero, an interrupt is generated.
  • Set up before scheduling a process, so the OS can regain control or terminate a program that exceeds its time.
Counter: 5
Press start to watch the counter drop to zero.

8. Resource Management

Process, memory and I/O management.

Process management

  • A process is a program in execution, a unit of work. A program is passive; a process is active.
  • Needs resources: CPU, memory, I/O, files, initialization data. These are reclaimed on termination.
  • Single-threaded process: one program counter. Multi-threaded: one program counter per thread.
  • Many processes (user and OS) run concurrently on one or more CPUs.
OS activities: creating and deleting user and system processes; suspending and resuming; process synchronization; process communication; deadlock handling.

Memory management

To run a program, its instructions and data (all or part) must be in memory. Goal: optimize CPU utilization and response time. Activities:
  • Keep track of which parts of memory are used, and by whom
  • Decide which processes and data to move into and out of memory
  • Allocate and deallocate memory space as needed

I/O subsystem

One purpose of the OS is to hide the peculiarities of hardware devices from the user. The I/O subsystem handles:
  • Buffering – temporarily storing data while it is transferred
  • Caching – keeping parts of data in faster storage for performance
  • Spooling – overlapping the output of one job with the input of other jobs

9. Chapter Summary

Review this right before the exam.

  • The OS manages hardware and sits between users and hardware; the kernel always runs.
  • CPUs and device controllers share memory over a bus; drivers (software) manage controllers (hardware).
  • Interrupts signal events: save state → find ISR via interrupt vector → run ISR → resume. A trap is a software interrupt.
  • The bootstrap program (firmware in ROM/EPROM) loads the kernel at startup.
  • Storage hierarchy: faster = costlier and smaller. Caching copies data to faster storage.
  • DMA moves blocks directly between device and memory: one interrupt per block.
  • OS types: Batch, Multiprogrammed, Time-sharing, Distributed, Network, Real-time, Multiprocessor.
  • Dual-mode (user/kernel, mode bit) and the timer protect the system.
  • OS manages processes, memory and I/O (buffering, caching, spooling).
