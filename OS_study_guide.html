What Is an Operating System?

ما هو نظام التشغيل؟
Definition & Goals التعريف والأهداف

An Operating System (OS) is a program that acts as an intermediary between a user and the computer hardware. It has two main roles:

Resource Allocator
Manages ALL hardware/software resources and ensures fair resource use among processes.
Control Program
Controls execution of programs to prevent errors and improper use of the computer.
🦕 Key fact: The one program running at all times on the computer is the Kernel. Everything else is either a system program or an application program.
Arabic Explanation
نظام التشغيل هو البرنامج الوسيط بين المستخدم ومكونات الحاسوب الصلبة. له دورين رئيسيين: مُخصِّص الموارد (يدير جميع الموارد بعدالة) وبرنامج التحكم (يتحكم بتنفيذ البرامج ويمنع الأخطاء). النواة (Kernel) هي البرنامج الوحيد الذي يعمل دائماً طوال وقت تشغيل الحاسوب.

Interrupts

المقاطعات
What Is an Interrupt? ما هي المقاطعة؟

An interrupt is a signal from a device or a program that causes the OS to stop its current task and handle the signal. The OS is interrupt driven.

Hardware Interrupt: Triggered by a hardware device (e.g., disk finished I/O, keyboard press). The device controller sends a signal to the CPU via the system bus.
Software Interrupt: Triggered by a program (via system calls or exceptions/errors in execution).
💡 When an interrupt occurs: CPU saves its current state, transfers control to the interrupt service routine (ISR), handles the event, then returns to what it was doing.
Arabic
المقاطعة (Interrupt): إشارة من جهاز أو برنامج تجبر المعالج على إيقاف ما يفعله والتعامل مع الحدث. نظام التشغيل مبني على مبدأ المقاطعات (Interrupt Driven). عند حدوث مقاطعة: المعالج يحفظ حالته الحالية، ينتقل لروتين معالجة المقاطعة، يعالج الحدث، ثم يعود لما كان يفعله.

Multiprocessing & OS Structure

تعدد المعالجات وهيكل نظام التشغيل
Multiprocessor Systems أنظمة متعددة المعالجات
TypeDescriptionبالعربي
Asymmetric MultiprocessingEach processor is assigned a specific task (master/slave)كل معالج له مهمة محددة
Symmetric Multiprocessing (SMP)Each processor performs all tasks; most commonكل معالج يؤدي جميع المهام
💡 Advantages of multiprocessors: (1) Increased Throughput — (2) Economy of Scale — (3) Increased Reliability (fault tolerance)
Arabic
Asymmetric: كل معالج له مهمة محددة (معالج رئيسي Master يوزع العمل). Symmetric (SMP): كل معالج يؤدي جميع المهام، الأكثر شيوعاً. مزايا تعدد المعالجات: زيادة الإنتاجية، اقتصاد في التكلفة، موثوقية أعلى (النظام يعمل حتى لو تعطل معالج).
Multiprogramming & Timesharing تعدد البرامج ومشاركة الوقت
Multiprogramming: Multiple jobs kept in memory simultaneously. When one job waits (for I/O), the OS switches CPU to another job — keeps CPU busy at all times.
Timesharing (Multitasking): CPU switches jobs so frequently that users can interact with each running job. Response time < 1 second. Each user has at least one process in memory.
🦕 Virtual Memory: Allows execution of processes that are NOT completely in memory — uses disk space as extension of RAM.
Arabic
Multiprogramming (تعدد البرامج): عدة مهام في الذاكرة معاً، عندما تنتظر مهمة (للـ I/O) يتحول المعالج لمهمة أخرى — يبقي المعالج مشغولاً دائماً. Timesharing (مشاركة الوقت): المعالج يتبدل بين المهام بسرعة كبيرة جداً تجعل المستخدمين يشعرون أن كل منهم لديه معالجه الخاص. الذاكرة الافتراضية: تتيح تنفيذ عمليات لا تكون بالكامل في الذاكرة الرئيسية.
User Mode vs Kernel Mode وضع المستخدم ووضع النواة
User Mode (mode bit = 1): Limited privileges. User programs run here. Cannot access hardware directly.
Kernel Mode (mode bit = 0): Full privileges. OS kernel runs here. Can execute any instruction and access all hardware.

Transition: User program makes a System Call → trap switches to Kernel Mode → OS handles request → returns to User Mode.

Timer: Used to prevent a process from hogging the CPU forever — generates an interrupt after a set period.

Arabic
User Mode (mode bit=1): وضع محدود الصلاحيات للبرامج العادية، لا تستطيع الوصول المباشر للأجهزة. Kernel Mode (mode bit=0): وضع مميز للنواة، تستطيع تنفيذ أي تعليمة. الانتقال: البرنامج يطلب System Call → يتحول للـ Kernel Mode → النواة تنفذ الطلب → تعود لـ User Mode. Timer: مؤقت يمنع البرامج من احتكار المعالج.
Virtualization & Mobile Computing الافتراضية والحوسبة المحمولة
Virtualization: Allows an OS to run as a guest inside another OS. VMM (Virtual Machine Manager) provides virtualization services. Examples: VMware, VirtualBox.
Emulation: Slower method when source CPU differs from target CPU.
Mobile OS: Smartphones and tablets. Leaders: Apple iOS and Google Android. Features: GPS, gyroscope, augmented reality. Use IEEE 802.11 Wi-Fi or cellular data.
Arabic
Virtualization (الافتراضية): تتيح تشغيل نظام تشغيل (Guest) داخل نظام تشغيل آخر (Host). المدير: VMM (Virtual Machine Manager). Emulation: أبطأ من Virtualization، تُستخدم عندما يختلف نوع المعالج. الأنظمة المحمولة: iOS وAndroid للهواتف الذكية، تدعم GPS والـ AR.

OS Services

خدمات نظام التشغيل
What Services Does an OS Provide? ما هي الخدمات التي يقدمها نظام التشغيل؟

Services for the User:

  • User Interface (UI): CLI, GUI, or Batch
  • Program Execution: Load and run programs
  • I/O Operations: Interface with devices
  • File-System Manipulation: Read, write, create, delete files/dirs
  • Communications: Shared memory OR message passing
  • Error Detection: Detect CPU, memory, device, program errors

Services for System Efficiency:

  • Resource Allocation: Allocate CPU, RAM, I/O to multiple users/jobs
  • Accounting: Track who uses what resources
  • Protection: Control access to system resources
  • Security: Defend against external attacks (authentication, firewalls)
Arabic
خدمات OS للمستخدم: واجهة المستخدم (CLI/GUI)، تنفيذ البرامج، عمليات الإدخال/إخراج، إدارة نظام الملفات، التواصل بين العمليات، كشف الأخطاء. خدمات OS لكفاءة النظام: توزيع الموارد، محاسبة الاستخدام، الحماية من الوصول غير المصرح به، والأمان ضد الهجمات الخارجية.

Process Concept & Memory Layout

مفهوم العملية وتخطيطها في الذاكرة
What Is a Process? ما هي العملية؟

A process is a program in execution. It is an active entity, while a program is a passive entity stored on disk.

One program can create multiple processes (e.g., multiple users running the same program simultaneously).

🦕 Program (passive, on disk) → loaded into memory → becomes Process (active, executing)

PCB — Process Control Block

كتلة التحكم بالعملية
What Is a PCB? ما هي كتلة التحكم بالعملية؟

The PCB (Process Control Block) is a data structure in the OS that stores all information about a process. Also called Task Control Block.

PCB contains:
• Process State (new, ready, running, waiting, terminated)
• Process Number (PID) — unique identifier
• Program Counter — address of next instruction
• CPU Registers — all register values
• CPU Scheduling Info — priorities, queue pointers
PCB also contains:
• Memory-Management Info — memory limits, page tables
• Accounting Info — CPU time used, time limits
• I/O Status Info — devices allocated, open files list
💡 When the CPU switches from one process to another (Context Switch), it saves the old process's state into its PCB and loads the new process's state from its PCB.
Arabic
PCB (Process Control Block): بنية بيانات تخزن كل معلومات العملية: حالتها، معرّفها (PID)، عداد البرنامج، قيم السجلات، معلومات الجدولة، حدود الذاكرة، معلومات المحاسبة، قائمة الملفات المفتوحة. Context Switch: عند تبديل المعالج من عملية لأخرى، يحفظ حالة العملية الحالية في PCB الخاصة بها ويحمل حالة العملية الجديدة من PCB الخاصة بها.

Process Creation & Termination

إنشاء العمليات وإنهاؤها
fork(), exec(), wait() — Zombie & Orphan الزومبي والأيتام
Process Creation:
• Parent process creates children via fork()
• Child identified by pid (process identifier)
• Child can load a new program via exec()
• Parent may wait for child: wait(&status)
• Forms a tree of processes
Cascading Termination: If parent terminates, all children must terminate too (OS initiates this).

Zombie Process: Child has terminated but parent has NOT called wait() — process entry stays in process table.

Orphan Process: Parent terminated WITHOUT calling wait() on child.
Arabic
إنشاء العمليات: العملية الأم تنشئ عمليات أبناء باستخدام fork(). يمكن للابن تحميل برنامج جديد بـ exec(). الأم تنتظر الابن بـ wait(). Cascading Termination: إنهاء متتالي — إذا انتهت الأم، ينهي النظام جميع أبنائها. Zombie Process: عملية ابن انتهت لكن الأم لم تستدعِ wait() بعد. Orphan Process: الأم انتهت دون أن تستدعي wait() للابن.

What Is a Thread & Why Use It?

ما هو الخيط ولماذا نستخدمه؟
Thread Definition & Benefits تعريف الخيط وفوائده

A thread is a basic unit of CPU utilization. A multithreaded process has multiple threads sharing the same: code section, data section, OS resources. Each thread has its own: thread ID, program counter, register set, and stack.

📱 Responsiveness: If one thread blocks, others continue running. Example: web browser can still scroll while loading an image.
🤝 Resource Sharing: Threads share process resources (memory, files) by default — no need for shared memory or message passing like between processes.
💰 Economy: Creating a thread is cheaper than creating a process. Context switching between threads is also faster.
📈 Scalability: Threads run in parallel on multiple cores — single-threaded process can only use ONE core regardless of how many are available.
Arabic
الخيط (Thread): الوحدة الأساسية لاستخدام المعالج. العملية متعددة الخيوط تشترك خيوطها في: الكود، البيانات، موارد OS. كل خيط له: معرّفه الخاص، عداد البرنامج، مجموعة السجلات، والمكدس الخاص. الفوائد الأربع: الاستجابة (Responsiveness)، مشاركة الموارد (Resource Sharing)، الاقتصاد (Economy — أرخص من العمليات)، قابلية التوسع (Scalability — يستفيد من متعدد المعالجات).

Parallelism vs Concurrency

التوازي مقابل التزامن
Key Difference الفرق الجوهري
Parallelism (توازي)
System performs MORE THAN ONE task simultaneously. Requires multiple cores/CPUs. Threads literally run at the exact same time.
Concurrency (تزامن)
System supports MORE THAN ONE task making progress. Can work on single core via rapid switching. Tasks appear to run simultaneously.
Data Parallelism: Distributes same data subset across cores, performs same operation on each.
Task Parallelism: Distributes different threads across cores, each performing a unique operation.
Arabic
Parallelism (توازي): تنفيذ أكثر من مهمة في نفس اللحظة الحقيقية — يتطلب متعدد المعالجات/الأنوية. Concurrency (تزامن): دعم تقدم أكثر من مهمة — يمكن على معالج واحد بالتبديل السريع. Data Parallelism: نفس العملية على أجزاء مختلفة من البيانات. Task Parallelism: خيوط مختلفة تؤدي عمليات مختلفة.

Many-to-Many: الأمثل، النظام يُنشئ ما يكفي من خيوط النواة. LWP: معالج افتراضي خفيف الوزن يربط خيوط المستخدم بخيوط النواة.

1

Basic Concepts & Criteria

المفاهيم الأساسية والمعايير
CPU–I/O Burst Cycle & Scheduling Criteria دورة CPU-I/O ومعايير الجدولة

Process execution consists of a cycle of CPU bursts and I/O waits. Histogram: many short CPU bursts, few long bursts.

The CPU Scheduler selects from the Ready Queue which process gets the CPU next.

CriterionGoalDescriptionبالعربي

2

Preemptive vs Non-preemptive

الجدولة الاستباقية وغير الاستباقية
When Does Scheduling Occur? متى تحدث الجدولة؟
Non-preemptive (غير استباقية): Process keeps CPU until it voluntarily releases it (terminates or waits for I/O). Scheduling only occurs at states 1 & 4.
Preemptive (استباقية): OS can forcibly take CPU from running process. Scheduling occurs at all state transitions. Used by virtually all modern OSes (Windows, macOS, Linux, UNIX).
Arabic
Non-preemptive: العملية تحتفظ بالمعالج حتى تنتهي أو تنتظر I/O. Preemptive (استباقية): نظام التشغيل يستطيع سحب المعالج من العملية في أي وقت. جميع أنظمة التشغيل الحديثة (ويندوز، لينكس، macOS) تستخدم الجدولة الاستباقية.
3

Scheduling Algorithms

خوارزميات الجدولة
FCFS — First Come First Served أولاً يأتي أولاً يُخدَم

Processes are served in the order they arrive. Non-preemptive.

⚠️ Convoy Effect: A short process stuck behind a long one. Causes high average waiting time when a long process arrives first.
Example: P1=24ms, P2=3ms, P3=3ms arriving in order P1,P2,P3
P10→24
P224→27
P327→30

Waiting time: P1=0, P2=24, P3=27 — Average = 17 ms

If order is P2,P3,P1 → Average waiting = 3 ms (much better!)

Arabic
FCFS: الأول يُنفَّذ أولاً، بسيط لكن غير مثالي. Convoy Effect: عملية طويلة تجعل جميع العمليات القصيرة تنتظر طويلاً خلفها. مثال: P1(24ms) يُنفَّذ قبل P2(3ms) و P3(3ms) → متوسط الانتظار 17ms. لو عُكس الترتيب → 3ms فقط!
SJF — Shortest Job First أقصر مهمة أولاً

Selects the process with the shortest next CPU burst. Optimal — gives minimum average waiting time.

Preemptive version: Shortest Remaining Time First (SRTF)

Example: P1=6ms, P2=8ms, P3=7ms, P4=3ms
P40→3
P13→9
P39→16
P216→24

Average waiting = (3+16+9+0)/4 = 7 ms

Arabic
SJF: ينفذ العملية الأقصر burst أولاً. الأمثل — يعطي أقل متوسط انتظار ممكن. لكن المشكلة: كيف نعرف طول burst القادم؟ (نقدّره). النسخة الاستباقية تسمى SRTF (Shortest Remaining Time First) وتسحب المعالج إذا وصلت عملية أقصر.
Round Robin (RR) الجدولة الدورية

Each process gets a small unit of CPU time called a time quantum (q) (usually 10–100ms). After q expires, process is preempted and added to the end of the Ready queue.

With n processes and quantum q: no process waits more than (n−1)×q time units.

💡 If q is very large → behaves like FCFS. If q is very small → overhead from too many context switches.
Example: P1=24ms, P2=3ms, P3=3ms, q=4ms
P10→4
P24→7
P37→10
P110→14
P114→18
P118→22
P122→26
P126→30
Arabic
Round Robin: كل عملية تحصل على شريحة زمنية (Time Quantum) محددة ثم تُسحب المعالج منها وتذهب لنهاية الطابور. مع n عملية وشريحة q → لا تنتظر أي عملية أكثر من (n-1)×q. أفضل response time من SJF لكن turnaround أعلى عادة.
Priority Scheduling — Starvation & Aging جدولة الأولوية — المجاعة والشيخوخة

Each process is assigned a priority number. CPU given to process with highest priority (smallest integer).

💡 SJF is a special case of Priority Scheduling where priority = inverse of next CPU burst length.
⚠ Problem: Starvation (المجاعة)
Low-priority processes may never execute because higher-priority processes keep arriving.
✅ Solution: Aging (الشيخوخة)
As time progresses, gradually increase the priority of waiting processes. Eventually a low-priority process becomes high-priority.
Arabic
Priority Scheduling: كل عملية لها أولوية، الأعلى أولوية (أصغر رقم) تُنفَّذ أولاً. Starvation (مجاعة): العمليات ذات الأولوية المنخفضة قد لا تُنفَّذ أبداً لأن العمليات ذات الأولوية العالية تأتي باستمرار. Aging (شيخوخة): الحل — نزيد أولوية العملية تدريجياً كلما طال انتظارها حتى لا تتجوع.
8

Deadlocks

الجمود (الإقفال الميت)
4 Conditions · Resource-Allocation Graph · Safe vs Unsafe State · Banker's Algorithm · Detection & Recovery
1

What Is a Deadlock? & The Four Conditions

ما هو الجمود؟ والشروط الأربعة
Deadlock Definition تعريف الجمود

A deadlock occurs when a set of processes are each waiting for a resource held by another process in the set, and none can proceed.

A system is in deadlock if and only if ALL FOUR of the following conditions hold simultaneously:

1. Mutual Exclusion الاستبعاد المتبادل

Only one process can use a resource at a time. If another requests it, it must wait until it's released.

Arabic
مورد واحد يُستخدم بعملية واحدة فقط في نفس الوقت. إذا طلبته عملية أخرى يجب أن تنتظر.
2. Hold & Wait الإمساك والانتظار

A process is holding at least one resource AND waiting to acquire additional resources currently held by other processes.

Arabic
عملية تمسك بمورد واحد على الأقل وتنتظر مواردً أخرى ممسوكة من عمليات أخرى.
3. No Preemption عدم الاستباقية

A resource cannot be taken away forcibly. It can only be released voluntarily by the process holding it after completing its task.

Arabic
لا يمكن سحب المورد قسراً من العملية. يُطلق فقط طوعاً عند انتهاء العملية من استخدامه.
4. Circular Wait الانتظار الدائري

A set of processes {P0, P1, ..., Pn} where P0 waits for resource from P1, P1 waits for resource from P2, ..., Pn waits for resource from P0. A circle of waiting.

Arabic
سلسلة دائرية من الانتظار: P0 ينتظر مورد P1، P1 ينتظر مورد P2، ... Pn ينتظر مورد P0.
2

Resource-Allocation Graph

مخطط تخصيص الموارد
RAG Components & Deadlock Detection مكونات المخطط واكتشاف الجمود
Request Edge: Process → Resource (dotted arrow: Ti → Rj)
Process Ti is requesting Resource Rj.

Assignment Edge: Resource → Process (arrow: Rj → Ti)
Resource Rj is assigned to Process Ti.
Rules:
• No cycle in graph → NO deadlock
• Cycle exists + ONE instance per resource → Deadlock!
• Cycle exists + multiple instances → Possible deadlock (not guaranteed)
Arabic
مخطط تخصيص الموارد (RAG): Request Edge: سهم من العملية للمورد (تطلبه). Assignment Edge: سهم من المورد للعملية (مُخصَّص لها). لا دورة في المخطط = لا جمود. دورة موجودة + مورد بنسخة واحدة = جمود مؤكد. دورة + نسخ متعددة = جمود محتمل (ليس مؤكداً).
3

Safe vs Unsafe State & Banker's Algorithm

الحالة الآمنة وغير الآمنة وخوارزمية المصرفي
Safe State & Banker's Algorithm الحالة الآمنة وخوارزمية المصرفي
Safe State: There exists a safe sequence <T1, T2, ..., Tn> where each Ti's remaining resource needs can be satisfied by currently available resources + resources held by all Tj (j < i). No deadlock possible in safe state.
Unsafe State
No safe sequence exists. The system may lead to deadlock (not guaranteed, but risky).
🦕 Safe → No deadlock. Unsafe → Possible deadlock. Deadlock → Always unsafe.

Banker's Algorithm is used for deadlock avoidance with multiple resource instances. It uses four data structures:

StructureTypeMeaningبالعربي
AvailableVector [m]Available[j] = # instances of resource Rj currently availableالموارد المتاحة حالياً
MaxMatrix [n×m]Max[i][j] = max instances of Rj that Ti may requestالحد الأقصى لما قد تطلبه كل عملية
AllocationMatrix [n×m]Allocation[i][j] = # instances of Rj currently allocated to Tiما هو مُخصَّص فعلياً لكل عملية
NeedMatrix [n×m]Need[i][j] = Max[i][j] − Allocation[i][j]ما تحتاجه كل عملية لتكتمل
💡 Key Formula: Need = Max − Allocation
Banker's Algorithm 4-Step Process
Step 1: Calculate Total Allocation for each resource type (A, B, C) Step 2: Calculate Remaining Need = Max - Allocation for each process Step 3: Calculate Available = Total Resources - Total Allocation Step 4: Check if Available >= Need for any process. If YES: execute that process, add its Allocation to Available, mark process as done, repeat from Step 4. If a safe sequence is found: system is in SAFE STATE. If no sequence works: UNSAFE STATE.
Example (5 processes, 3 resource types A=10, B=5, C=7)
ProcessAllocation (A B C)Max (A B C)Need (A B C)Available (A B C)
T00 1 07 5 37 4 33 3 2
(initial)
T12 0 03 2 21 2 2
T23 0 29 0 26 0 0
T32 1 12 2 20 1 1
T40 0 24 3 34 3 1
✔ Safe Sequence: <T1, T3, T4, T2, T0> — System is in SAFE STATE
Arabic
خوارزمية المصرفي (Banker's Algorithm): تتجنب الجمود بتحديد ما إذا كان منح الموارد سيُبقي النظام في حالة آمنة. البيانات الأربعة: Available (الموارد المتاحة)، Max (الحد الأقصى للطلب)، Allocation (المُخصَّص حالياً)، Need = Max - Allocation (ما تحتاجه كل عملية). الخطوات: احسب الـ Need، احسب Available، جد تسلسلاً آمناً. إذا وُجد → حالة آمنة. إذا لم يوجد → حالة غير آمنة.
4

Deadlock Handling Methods & Recovery

طرق معالجة الجمود والتعافي
Three Approaches & Recovery ثلاثة مناهج والتعافي
1. Prevention
Ensure at least ONE of the 4 conditions never occurs. Hard to implement, limits resource use.
2. Avoidance
Use Banker's Algorithm to never enter an unsafe state. Requires prior knowledge of max resource needs.
3. Detection & Recovery
Allow deadlocks, detect them, then recover (kill processes or preempt resources).

Recovery Options:

Resource Preemption: Forcibly take resources from a process and give them to another. Rollback required.
Process Termination: Either kill ALL deadlocked processes (costly) or kill ONE at a time until deadlock is resolved.
Arabic
ثلاثة مناهج لتعامل مع الجمود: المنع (Prevention): منع حدوث إحدى الشروط الأربعة، صعب التطبيق. التحاشي (Avoidance): استخدام خوارزمية المصرفي لعدم الدخول في حالة غير آمنة. الكشف والتعافي (Detection & Recovery): السماح بالجمود ثم اكتشافه والتعافي منه بإنهاء عمليات أو سحب موارد.

📋 Exam Questions & Model Answers أسئلة الامتحان والإجابات النموذجية

Q1 — Ch1
What is an Operating System? What are its two main roles?
✔ An OS is a program acting as intermediary between user and hardware. Two roles: (1) Resource Allocator — manages all resources fairly. (2) Control Program — controls program execution to prevent errors.
Arabic
نظام التشغيل: وسيط بين المستخدم والأجهزة. دورين: (1) مُخصِّص الموارد (يدير الموارد بعدالة). (2) برنامج التحكم (يمنع الأخطاء والاستخدام الخاطئ).
Q2 — Ch1
What is the difference between Multiprogramming and Timesharing?
✔ Multiprogramming: multiple jobs in memory, CPU switches when job waits for I/O — maximizes CPU utilization. Timesharing: CPU switches so frequently users can interact with each running job — response time < 1 sec. Timesharing = logical extension of multiprogramming.
Arabic
Multiprogramming: عدة مهام في الذاكرة، يتحول المعالج للمهمة التالية عند الانتظار. Timesharing: تبديل سريع جداً يسمح للمستخدمين بالتفاعل مع كل مهمة. Timesharing = امتداد منطقي للـ Multiprogramming.
Q3 — Ch1
What is User Mode vs Kernel Mode? How does transition occur?
✔ User Mode (mode bit=1): limited privileges, user programs. Kernel Mode (mode bit=0): full access, OS kernel. Transition: user program makes a System Call → trap sets mode bit=0 → OS handles → returns to User Mode (bit=1).
Arabic
User Mode (bit=1): محدود الصلاحيات. Kernel Mode (bit=0): كامل الصلاحيات. الانتقال: System Call → trap → Kernel Mode → تنفيذ → User Mode.
Q4 — Ch2
List the 6 types of System Calls with examples for each.
✔ (1) Process Control: fork(), exec(), exit(). (2) File Management: open(), read(), write(). (3) Device Management: request(), release(). (4) Information Maintenance: gettime(), getpid(). (5) Communications: send(), receive(), connect(). (6) Protection: get/set permissions, allow/deny access.
Q5 — Ch3
What are the 5 process states? Draw the transition diagram.
✔ New → Ready ↔ Running ↔ Waiting → Terminated. New → Ready (admitted). Ready → Running (dispatched by scheduler). Running → Waiting (I/O request). Waiting → Ready (I/O done). Running → Terminated (exit).
Arabic
الحالات: New → Ready ↔ Running ↔ Waiting → Terminated. الانتقالات: admitted, dispatch, I/O wait, I/O done, exit.
Q6 — Ch3
What is a PCB? What information does it contain?
✔ PCB (Process Control Block) is a data structure storing all process information: process state, PID, program counter, CPU registers, CPU scheduling info, memory limits, accounting info, I/O status and open files list. The OS uses PCB for context switching.
Arabic
PCB: بنية بيانات تحفظ كل معلومات العملية. تُستخدم عند Context Switch لحفظ وتحميل حالة العملية.
Q7 — Ch3
What is the difference between Zombie and Orphan processes?
✔ Zombie: child process has terminated but parent has NOT called wait() — entry remains in process table. Orphan: parent has terminated WITHOUT calling wait() on a still-running child process.
Arabic
Zombie: الابن انتهى لكن الأم لم تستدعِ wait(). Orphan: الأم انتهت دون انتظار الابن.
Q8 — Ch4
What are the 4 benefits of multithreading?
✔ (1) Responsiveness: app continues if one thread blocks. (2) Resource Sharing: threads share memory/resources by default. (3) Economy: creating threads cheaper than processes. (4) Scalability: threads run in parallel on multi-core, unlike single-threaded processes.
Arabic
(1) الاستجابة (2) مشاركة الموارد (3) الاقتصاد — أرخص من العمليات (4) قابلية التوسع — يستفيد من متعدد المعالجات.
Q9 — Ch5
Compare FCFS, SJF, and Round Robin scheduling algorithms.
✔ FCFS: non-preemptive, simple, convoy effect problem. SJF: optimal (minimum avg waiting time), preemptive version=SRTF. Round Robin: time quantum q, best response time, max wait=(n-1)×q, preemptive.
Arabic
FCFS: بسيط، غير استباقي، تأثير القافلة. SJF: الأمثل، SRTF نسخته الاستباقية. RR: شريحة زمنية، أفضل response time.
Q10 — Ch8
What are the 4 necessary conditions for deadlock? How do we prevent it?
✔ (1) Mutual Exclusion (2) Hold & Wait (3) No Preemption (4) Circular Wait. ALL four must hold simultaneously. Prevention: eliminate at least one condition. Avoidance: Banker's Algorithm. Detection & Recovery: allow deadlock, then kill/preempt.
Arabic
الشروط الأربعة: الاستبعاد المتبادل، الإمساك والانتظار، عدم الاستباقية، الانتظار الدائري. لمنع الجمود: أزل شرطاً واحداً. للتحاشي: خوارزمية المصرفي.
Q11 — Ch8
Explain the Banker's Algorithm. What does Need = Max - Allocation mean?
✔ Banker's Algorithm avoids deadlock by checking if granting a request keeps system in safe state. Need = Max - Allocation: the remaining resources a process needs to complete.
